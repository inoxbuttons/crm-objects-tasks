## Решения и допущения (черновик для DECISIONS.md)
1. Роль хранится в `profiles`, задаётся при создании пользователя через `app_metadata`; пользователь сменить её не может.
2. Любой постановщик видит и принимает любые задачи (ТЗ: «видит всё»), не только свои.
3. Исполнитель видит в карточке объекта только свои задачи, а не все задачи объекта.
4. Имена всех пользователей видны всем авторизованным (нужно для истории и выбора исполнителя). Email и роль чужих — тоже; при желании можно ограничить.
5. Удалить задачу можно только в статусе «Новая»; дальше удалять нельзя, чтобы не терять историю.
6. Объект с задачами удалить нельзя.
7. Принятую задачу редактировать нельзя (закрыта).
8. Переназначить исполнителя постановщик может в любом статусе, кроме «Принята»; в историю статусов это не пишется (история — только про статусы, как в ТЗ).
9. Справочник переходов хранится в БД и используется и сервером, и интерфейсом — одно место правды.
10. Без realtime: данные обновляются после действий и при переходе между экранами.
Не успели / вне скоупа: сброс пароля, пагинация, поиск, вложения, уведомления, e2e-тесты UI.
